# Design System

> Este documento define el lenguaje visual oficial de S&A. Todo componente, pantalla o animación debe respetar las reglas descritas aquí. El objetivo es garantizar una experiencia consistente, elegante y mantenible en toda la aplicación.

---

# Objetivo

El Design System existe para responder una única pregunta.

¿Cómo debe verse S&A?

Toda decisión visual debe poder responderse consultando este documento.

No deben existir decisiones de diseño improvisadas.

---

# Filosofía

El sistema visual de S&A está construido sobre cinco pilares.

- Simplicidad
- Elegancia
- Consistencia
- Legibilidad
- Emoción

No diseñamos para impresionar.

Diseñamos para acompañar recuerdos.

---

# Colores

## Filosofía

El color principal representa la identidad del proyecto.

No debe dominar la interfaz.

Debe aparecer como una firma.

Como un detalle.

Nunca competir con las fotografías.

---

## Color principal

Vinotinto.

Representa:

- cariño
- elegancia
- intimidad
- calidez

Debe utilizarse únicamente para:

- botones importantes
- enlaces activos
- pequeños acentos
- indicadores
- estados seleccionados

Nunca utilizarlo como fondo completo de la aplicación.

---

## Colores neutros

La mayor parte de la interfaz utilizará colores neutros.

El fondo siempre debe favorecer la fotografía.

La fotografía es el elemento con mayor prioridad visual.

---

# Tipografía

Fuente oficial

Outfit

No introducir nuevas familias tipográficas.

---

## Jerarquía

La jerarquía visual debe construirse mediante:

- tamaño
- peso
- espacio

Nunca mediante colores exagerados.

---

## Estilo

La tipografía debe sentirse:

- moderna
- limpia
- cercana
- elegante

---

# Espaciado

Todo el proyecto utilizará una única escala.

Ejemplo.

4

8

12

16

24

32

48

64

96

128

Nunca utilizar valores arbitrarios.

Si aparece un nuevo espaciado.

Debe añadirse oficialmente al sistema.

---

# Bordes

Los radios deben mantenerse consistentes.

No utilizar radios diferentes en componentes similares.

---

# Sombras

Las sombras existen únicamente para aportar profundidad.

Nunca dramatismo.

Nunca exageración.

Las sombras deben sentirse invisibles.

---

# Glass

El efecto glass es parte de la identidad visual.

Debe utilizarse únicamente cuando mejore la jerarquía.

Nunca abusar del desenfoque.

Nunca crear interfaces completamente transparentes.

---

# Motion

Las animaciones forman parte del diseño.

No son un añadido.

Toda transición debe comunicar continuidad.

Nunca espectáculo.

---

## Curva oficial

cubic-bezier(.22,1,.36,1)

No utilizar curvas distintas salvo que exista una razón muy clara.

---

## Duraciones

Micro interacción

150ms

Interacción

280ms

Cambio de pantalla

500ms

Mantener consistencia.

---

# Componentes

Todo componente debe pertenecer al Design System.

Actualmente existen componentes base.

Ejemplos.

Button

IconButton

Typography

Container

Section

GlassPanel

Card

Con el crecimiento del proyecto se añadirán más componentes.

Nunca duplicar estilos.

---

# Responsive

Desktop tiene prioridad.

Posteriormente.

Tablet.

Finalmente.

Mobile.

Nunca romper la experiencia de escritorio para mejorar dispositivos pequeños.

---

# Accesibilidad

Toda interfaz debe ser:

- navegable mediante teclado
- legible
- con contraste suficiente
- compatible con lectores de pantalla cuando sea posible

La accesibilidad forma parte de la calidad del producto.

---

# Imágenes

Las imágenes representan el contenido principal.

Nunca reducir su protagonismo.

Siempre priorizar:

- buena escala
- buena composición
- transiciones suaves
- carga progresiva

---

# Videos

Los videos son ciudadanos de primera clase.

Comparten las mismas reglas visuales que las fotografías.

No deben sentirse como un contenido especial.

---

# Consistencia

Si dos componentes cumplen la misma función.

Deben verse iguales.

Si dos pantallas pertenecen al mismo módulo.

Deben compartir el mismo lenguaje visual.

---

# Evolución

El Design System crecerá junto con el proyecto.

Toda nueva decisión visual deberá registrarse aquí antes de convertirse en una convención oficial.

---

# Regla de oro

Si un componente rompe la consistencia del sistema.

El componente debe cambiar.

Nunca el sistema.
